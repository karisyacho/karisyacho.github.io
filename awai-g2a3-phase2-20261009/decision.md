# AWAI — G2-A 技術・体験設計の最終判断

2026-10-09／設計判断のみ。実装・本編統合・実機検証は今回行っていない。

**採用方式はB。Gridは接触の手応えとなる小変形に限定し、奥の世界の発見は独立した光学表現で担う。** 大変形を完成条件から外す。Gridの力学研究を次工程の主題にしない。

## 1. 判断の根拠と3方式の比較

### 確認できた事実

- [公開Gridレポート](https://karisyacho.github.io/awai-g2a2-grid-20261009/report.html?v=a760a7f)と手元の実装・計測記録、G1/G1.5設計、Smooth/Gridの時系列比較画像を確認した。録画はスマホ寸法のブラウザ収録で、実機収録ではない。今回は計測を再実行していない。
- 既存測定の主接点では、投影面積比の最小値がPCで0.505→0.982、SPで0.352→0.945。Gridは圧縮を抑えている。一方、稜線の横／縦最大移動はPC 1.60／2.20px、SP 2.05／2.48px。SPの合成移動最大は3.18pxであり、「移動量すべてが2px」とは扱わない。
- 深さPC約4.2%H／SP約3.3%Hは、画面上の横移動ではない。大きい深さだけでは触った結果が明瞭になるとは言えない。
- 曲率指標は全面的には改善していない。追加沈みHessian RMSはPC 0.646→1.672、SP 1.048→3.884。Gridを自然な膜の完成解とは扱わない。
- 解除中solver平均はPC 2.86ms／SP寸法1.96ms per callbackという既存PC上の測定。GPU実行時間・スマホFPS・発熱は未測定。
- `material.js`の現行Bは琥珀色とノイズの加算で、奥の景色を描いていない。`strain = materialLoad * uAmount`は入力由来の演出量であり、Gridの辺長から得た実測ひずみではない。

以下の比較は、上の事実を踏まえた**設計上の見込み**。A/B/C完成品の実測比較や料金見積りではない。今回の方式Bと、既存プレビューの材質切替「B」は別の意味である。

| 判断基準 | A：Gridの大変形を改良 | B：小変形＋奥の像 | C：材質・光景中心、動的Gridなし |
|---|---|---|---|
| モード・前衛的な美術 | うまく行けば強いが、谷・ゴム感・構図変化の再発リスク | 静止構図を保ちながら、局所的な異変を作りやすい | 制御しやすいが、平面的な照明効果に見える懸念 |
| 接触変化の分かりやすさ | 変形が見えても「奥の世界」まで伝わるとは限らない | 奥の像の可視性を直接調整できる | 同様に直接調整できる。膜に触れた感覚は別途必要 |
| スマホ操作 | 指の遮蔽、縦スクロール、復元待ちの影響が大きい | 短いタップでも指の周囲に反応を残せる | 最も単純化しやすい |
| 60〜90秒本編との接続 | 変形研究と物語の接続を別々に解く必要 | S1の同じ像を予告し、そのまま転換へ受け渡せる | Bと同じ接続が可能 |
| 実装コスト | 高い・不確定。境界変更は静止美術の再調整にも及ぶ | 中。既存形状と入力を残し、光学表現を置換 | 低〜中。軽量化できるが手応えの再設計が必要 |
| 性能 | 現状以上の計算負荷になる可能性 | Grid分の負荷を残す。実機合格が必要 | 動的Gridを省ける分、有利と予想 |
| G1との整合 | 動的な構図逸脱に注意 | 黒・斜めの張力・左上光・S0/S4同一面を維持可能 | 静止美術を維持可能。変形の意味は弱まる |
| コード再利用 | solverを残せるが制約系の変更が波及 | 基準形状・solver・描画・入力・寿命管理を広く再利用 | 基準形状・材質・入力は再利用、solverは不要 |

**Aを却下する理由：** 不可能だからではなく、今の目的への寄与に対して不確定な作業が大きいから。外周固定を緩めたり余長を入れれば大変形の可能性はあるが、G1の張力・稜線を保ったまま良くなる証拠はない。さらに、大きく凹むことと奥の発見は別問題である。

**Cを第一採用にしない理由：** 既存Gridには小変形・復元・入力の土台があり、まずそれを限定利用する方が接触感を捨てずに検証できる。ただし、既存投資の回収だけを理由に残さない。後述のGrid無効比較で体験差がない、または実機性能を満たさない場合はCへ縮退する。Cを美術的に劣る方式と断定しない。

## 2. 体験とG1/G1.5の扱い

触れると黒い面がわずかに応じ、その奥に金属の弧と焙煎の暖かさが見える。指を横へ動かすと、光が指について歩くのではなく、そこに元からある像の違う部分が見える。これを発見の核にする。

黒い膜の斜めの稜線、左上光、黒い余白、HTML文字、S0/S4共通の基準形状を維持する。白い面、藍、粒子、発光する輪郭、円形の穴、破れ、めくれは加えない。

**G1.5からの変更点は明示する。** G1.5の「タッチ中は不透明、奥の開示は転換時のみ」を、「面の連続性は保ち、接触中に奥の像を部分的に知覚できる」へ変更する提案である。最終描画のalphaを1に保っても、知覚上の透過を導入するため、従来方針を完全維持したとは言わない。G1の静止美術とは両立可能だが、G1.5の体験仕様は改訂となる。

S0→S1は従来の稜線への接近・暗部でのカットを維持し、接触中に見えた金属の弧をS1の同じ像へ受け渡す。S0で世界全体を見せ切らない。接触は発見の機会であり、進行の鍵ではない。触らず縦スクロールしてもS1へ進む。

本編60〜90秒に対し、S0の滞在は8〜12秒程度を編集上の初期目安とする。強制待機時間やタイマーによる自動送りではない。接触回数や長押し成功を進行条件にしない。

対象は `docs/awai/g2a-grid/`。以下は移植方針であり、今回は変更していない。

| `grid-model.js` | 既存の距離制約・曲げ・固定境界・局所荷重・復元・減衰。初回は格子数、力、反復数を増やさない。Gridを無効化できる境界を設ける |
| `grid-shader.js` | 基準形状＋差分変位、補間、変位に対応した法線。補間面全点でひずみ保証があるとは扱わない |

## 4. 新しい試作では不要な処理

- Clear/Dramatic/Smoothの大変形経路、指定稜線warp、谷・圧縮を後処理で抑える調整を、新試作の本経路へ持ち込まない。旧比較資料・旧コードは削除しない。
- 稜線の大移動を目標とした境界再設計、格子細分化、反復増加、非線形シェル、自己接触、流体、実物の薄さ・屈折率の推定は不要。
- `strain`を物理ひずみとみなす光学駆動は廃止。接触から得る演出量として名前と意味を明確にする。
- `backPlate`のノイズと単色の加算だけで「別世界を発見した」と判定しない。既存A/B材質比較・多数のsliderは研究画面に残し、本編には出さない。
- `settle()`の300 substep一括実行を、動きを減らす設定の操作ごとに呼ぶ経路は採用しない。静止形状と奥の像の状態切替で代替する。

## 5. 最小限の検証プロトタイプ

**範囲：S0とS1への接続見本だけ。** KASANE、AIMA、全編統合、新しい物理方式、動画素材生成は行わない。

最初に「静止→接触→S1」の3状態を一枚の見た目案として提示し、方向を確認してから操作を組む。G1の承認を、今回の奥の像の見せ方まで承認済みと解釈しない。

奥の像には既存G1のS1-PC/SPを仮plateとして各1枚使う。架空の生成見本であり、本番素材の採用承認とは別。金属の弧と琥珀の位置をS1と合わせる。最初は静止画、固定したぼけ、固定した暗さのみとし、動画・動的ぼかし・追加3D空間は不要。

別レイヤーとは**論理的な描画要素**を意味する。別canvas・別WebGLコンテキスト・追加の物理シミュレーションは作らない。奥のplateは画面／場面に固定し、指の座標でplate自体を移動させない。接触の影響域だけが動く。

接触位置を起点に、稜線方向へ長く伸びる柔らかな領域で奥の像を見せる。指の直下だけに閉じず、周囲へ読める部分を出す。輪郭のはっきりした楕円・円形スポットは不可。膜の稜線と繊維の遮蔽を残す。全画面の露出を上げて反応を作らない。

以下の時間は**新たな設計目標であり、実測値ではない**。

| 状態 | 初期仕様 |
|---|---|
| 静止 | 現行Gridの光オフ基準。未接触時の奥の寄与はゼロ |
| 接触開始 | 100ms以内に小さな面／陰影反応。奥の像も立ち上がりを始める |
| 100〜150ms程度の短いタップ | 離した後も含め500〜700ms程度、反応を読み取る機会を確保。通常のタップのみ。縦scrollやcancelで疑似タップを発火しない |
| 0.8秒の静止接触 | 説明なしでも奥に形があると読める状態へ。長押し必須にはしない |
| 横移動 | 接触領域は移動するが、奥の金属の弧は場面内の同じ位置に残る |
| 解除 | 光学的な余韻は0.5〜0.9秒で消す。Gridは既存の自然復元を当初維持し、進行を待たせない |
| 縦移動・cancel | 入力を解除し、縦scroll・ピンチ・端のOS操作へ譲る。転換を即座に受け付ける |
| 動きを減らす設定 | 動的Gridと視点移動を止め、固定形状＋奥の像の状態切替で意味を残す |

比較条件は3つだけ：現行Grid光オフ／新B／新BのGrid無効。最後の条件はCへの縮退判断用で、別作品を作るものではない。奥の素材・入力・光学タイミングは新Bと揃え、Gridの寄与だけ比較する。

## 6. Sol高へ渡す実装指示

実行時のモデルは本人の「Sol高」指定に従う。今回は担当の起動・設定変更・実装を行わない。

1. 旧Grid/Smoothを変更せず、独立した新試作を作る。他担当の変更を戻さない。まず上記3状態の見た目案を提示し、合意後に操作実装へ進む。
2. 基準形状・Grid solver・入力の寿命管理を移植する。初回のsolver設定は現状固定。大移動を取り戻す変更を加えない。
3. 状態を「接触量」「奥の像の可視量」「場面転換進度」に分ける。共通の接点と接触イベントで同期させるが、奥の可視量をGrid変位／実測ひずみの大きさへ従属させない。演出用のスカラー応答で十分。
4. `material.js`の旧琥珀・透過加算を、新しいplateの減衰合成へ置換する。固定された場面座標でplateを読む。膜の遮蔽と微細な質感を残し、出力alphaは1。線形色で合成し、最後に一度だけsRGBへ変換する。これは美術用の光学近似であり、正確な光輸送とは呼ばない。
5. `renderer.js`はPC/SPで必要なplate一枚だけ保持する。新規の常時render target、ping-pong更新、毎フレームblurは追加しない。静止と収束後は更新を停止する。
6. 短いタップの表示保証を、`settings.pull > 0`など旧変形方式の条件から分離する。縦移動・複数指・cancelを通常のpointerupと区別する。指圧APIを必須にしない。
7. G1.5のS0→S1接続見本を作る。操作中でも進度が転換に入れば接触受付を閉じる。光学状態の引継ぎを行い、S1に同じ金属の弧が見えることを確認する。無操作経路も同じS1へ着地する。
8. 比較3条件と合格条件だけを検証する。スマホ実機を使えなければ、機種・FPS・熱の欄は未検証と報告し、本番合格にしない。
9. 納品はスマホHTTPSプレビュー、短い実機録画、機種／OS／ブラウザ／品質別の結果表。新BとGrid無効の差が読めない、またはGridが性能予算を超える場合は、その一点を報告してCへの縮退判断へ戻す。物理研究を自動再開しない。

## 7. 美術・操作・性能の合格条件

以下は**今後の受入基準**であり、現行Gridや新Bが達成済みという意味ではない。

### 美術と発見

- 未接触・光学効果収束後は、同じ画面条件の現行Grid光オフ基準から最大1/255以内の画素差を目安とする。G1画像との完全一致は要求していない。新しい局所表現は別途G1構図との重ね合わせで評価する。
- 通常速度・スマホ原寸で、谷の折れ、繊維の潰れ、ゴム状の反跳、円形穴、光る縁、全画面のオレンジ化が見えない。既存の曲率最大値だけを合否にしない。
- 初見5人のうち4人以上が、一度触れた後に誘導なしで「自分の操作で変わった」「奥に何か／別の空間がある」の両方を説明できることを、小規模検証の目安とする。統計的な有効性の証明とはしない。
- 5人比較は提示順を入れ替える。Gridありの方が膜への接触感を増すと3人以上が判断し、破綻の指摘が増えないことを、Gridを残す最低限の根拠とする。差が出なければCを選び直す。
- 黒・稜線・左上光・S0/S4同一性は本人の美術確認を要する。発見テスト合格だけで美術承認としない。

### 操作と接続

- 有効な接触から最初の見える反応まで、実機で100ms以内。ソフトウェア時刻差と画面収録の確認を分けて記録する。
- 短いタップ、0.8秒保持、横移動、連打、縦scroll、pointercancel、2本指、回転で、固着・誤った再発火・進行不能がない。
- 主接点(0.42,0.55)に加え既存3接点で確認。暗い余白側でも指の外に変化が見える。端・文字の除外域は操作対象に数えない。
- 触った経路と触らない経路が同じS1へ進む。復元待ちや接触達成条件で止めない。奥の像が転換時に別位置へ飛ばない。
- 小さいスマホ幅320pxと390pxの構図を確認。実機iPhone/SafariとAndroid/Chrome各1台以上で縦操作、ブラウザバー変化、低輝度時の黒と反応を確認。録画だけで画面の黒視認性を判定しない。

### 性能と停止条件

- 代表2実機で60秒連続操作し、60Hz換算のフレーム間隔p95が20ms以下、33.3ms超の間隔が全体の1%未満を初期目標とする。ブラウザのRAF間隔は提示間隔の近似であり、GPU実行時間とは別記する。
- 同じ実機・同じ記録区間でsolverのCPU p95は3ms以内を目標とする。現行のPC上平均値から達成を推定しない。GPU実行時間を取得できない場合は未測定と記載する。
- 発熱確認は3分反復で行い、最後の60秒でも上記フレーム基準を満たす。1回の短い録画で熱安定性を合格にしない。
- 背景タブ・画面外は継続solverを停止。収束後の無操作時に定常的なRAFを回さない。再接触は即時再開し、復帰時の過去時間をまとめて追いつかせない。
- 不合格時はまず既存Balanced／DPR制限で画質と再計測を確認。それでもGridの寄与が小さい、または性能を満たさなければ動的Gridを止めてCへ縮退する。格子を複雑化して救済しない。

今回の判断は、**発見を光学表現で成立させ、Gridにはその発見を支えるだけの役割を与える**こと。本番採用の確定は上記の小さな検証で行う。
