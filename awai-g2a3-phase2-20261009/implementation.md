# AWAI G2-A3 Phase 2 — 触れる発見

状態：体験評価待ち。本番採用・実機性能・美術の最終承認ではない。

## 今回の実装

Phase 1の仮承認を受け、S0とS1への短い接続見本を独立して実装。方式B（既存Gridの小変形＋独立した奥の像）を維持した。Gridの力・格子・反復・制約・復元は変更していない。旧Grid/Smooth/Phase 1と既存公開サイトは保存する。

接触荷重、奥の可視量、スクロール進度を分離した。ポインター開始時にCPU側の描画を即座に送信し、接触荷重は24/sで立ち上げる。短いタップは解除後にも可視量を補助し、最初の600ms程度に読む機会を残す。保持では可視量が約0.8秒でほぼ最大になる。通常の解除では可視量を700msで消し、膜は既存Gridの自然復元を続ける。短タップの補助を含む完全消失時間は通常解除と異なり、開始から約980ms。可視量が残ることと、実際に視認できることは別に評価する。

奥の像は固定したG1 S1-PC/SP各1枚。指の座標をplateのUV・拡大率・ぼかしへ渡さない。横移動では稜線方向の非対称な可視領域だけが移動する。繊維・稜線の遮蔽を残し、円形穴・光る輪郭・指に追従するスポットライトを追加していない。

Phase 1の暗さを認識し、接触領域内の固定合成係数を変更した。plate係数0.52→0.78、合成減衰0.42→0.60。これは線形色の演出係数で、実測の透過率ではない。未接触の露出・照明は変えない。金属の弧、湯気、珈琲豆の反射を見せるが、「珈琲の世界」と説明なしに読めるかは未承認。

## 操作と進行

- PC：クリック・保持・横ドラッグ。マウス押下時にcaptureし、画面外・blurでも解除する。
- スマホ：タップ・静止接触・横移動。touch captureやpreventDefaultを使わず、touch-actionはpan-y pinch-zoom。
- 縦移動12px超、scroll、pointercancel、複数指では通常のタップ補助を発火させない。
- 文字と外周8pxを接触対象から除く。保持や接触回数を進行条件にしない。
- 縦スクロールは独立したpassive可視量と転換進度を駆動。進度0.45を超えると接触受付を閉じ、同じ像をS1へ受け渡す。接触した経路も無操作経路も同じS1へ着地する。
- reduced-motionでは動的Gridを止め、固定面で像を見せる。視点移動は追加していない。

開発用ヘッダーのGrid切替、品質、同操作再生、G1重ね合わせは体験用美術から分離した。録画用 `?clean=1` はヘッダーと操作案内を隠す。録画の指と操作名は収録時にだけ加えた注記で、プレビューの演出には含めない。

## 描画と性能設定

既存の単一WebGL2コンテキストに膜と奥の像を合成。線形色で合成し、一度だけsRGBへ変換、最終alphaは1。奥の像を別canvas・追加3D空間・物理的屈折シミュレーションとして作っていない。

Fullが初期設定。描画メッシュは256×192、既存Balancedは192×144。Grid計算格子はどちらも既存PC64×40／SP32×64で同じ。品質切替では描画メッシュとDPR上限を変え、Gridの計算設定は変えない。Balancedは無条件に適用せず、見た目と性能を比較するために残す。

収束後のRAFを停止。背景・画面外では描画とsolverを止め、復帰時に過去時間を一括計算しない。context lossで静止表示へ移り、復旧時に再構築する。pagehide/destroyでタイマー・入力・observer・WebGL資源を解放し、Grid参照も破棄する。静止撮影用settleは操作経路で呼ばない。

WebGL非対応時は現行Gridの静止画を表示し、面の接触操作を無効にする。縦スクロールによるS1の静止画への進行は残す。これは接触の発見体験の代替合格ではない。

## 録画と比較

PC1440×900／スマホ390×844、Full、Gridあり／なしの4本。短タップ120ms、保持1.2秒、横移動0.32→0.64（基準UV、y=0.55）、解除を同じスケジュールで収録。主接点は(0.42,0.55)、荷重1。MP4はH.264 / yuv420p / faststart。スマホで再生・保存できる。

接続はスマホ寸法で接触後／無操作の2本。接続動画のスクロールは同じ進度をブラウザで送る収録用操作で、ネイティブ縦ジェスチャーとの競合は別の自動テストで検証した。収録条件とソフトウェア描画送信時刻は recordings.json に記録。

全てデスクトップEdgeのブラウザ収録。スマホ寸法の動画を実機録画と呼ばない。録画の滑らかさやCPU送信時刻から実機の表示遅延・FPS・熱を推定しない。

## 検証結果

自動検証の実測値は evidence/verification.md と verification.json。入力・停止・解放・静止復帰・同条件光学・固定像・S1同一到達を確認する。性能はPC上の独立したブラウザで60秒ずつ、Gridあり／なし×Full／Balancedの4条件を記録する。RAF間隔は提示間隔の近似、CPU draw時間はGPU実行時間ではない。

4条件の記録区間は約60.4〜60.6秒。Gridありのsolver CPU p95はFull 3.9ms／Balanced 3.8msで、判断書の3ms目安を超えた。Gridなしはsolver実行0。描画品質を下げてもGridの計算設定は同じため、CPU負荷はほとんど変わらなかった。

測定時のRAF p95は4条件とも約6.1ms、33.3ms超は約0.054〜0.055%。このPC headless環境は約180HzのRAFスケジューリングで、60Hz実機のFPS合格とは扱わない。実機での判定は未検証。測定の完了を示す自動検査PASSと、性能目標を満たすことは区別する。Gridを残す性能上の根拠はまだ不足している。

通常の開発ヘッダーを表示したPCで、小数ピクセルの丸めにより最下端の進度が1未満となる点を修正した。終点まで1 CSS px以内なら進度を1へ確定する。320／390／1440px幅で終点を再確認し、endpoint-regression.jsonに記録。接触計算・光学タイミング・性能設定は変更していない。

## 既知の問題・未確認

- 暗い余白への接触、PCの小さい表示、低輝度では、奥の像が模様に読める危険が残る。固定像の中に物体があることと、説明なしに別世界を発見することは同じではない。
- 金属の弧を丸い穴の縁に読まないか、繊維を通した像が表面の模様に見えないかは美術・体験評価を要する。
- Gridの見た目の差は小さい。体験への寄与が小さければ動的Gridを廃止する候補。比較を維持し、評価を待つ。新しい物理研究で差を救済しない。
- G1 S1は生成キーフレームによる仮素材。実写の助任の素材として承認されたものではない。
- G1 S0との稜線幅・繊維の細部・明暗の差は現行Grid由来で残る。今回の主題にせず、重ね合わせを維持した。
- 実機iPhone/Safari・Android/Chrome、ブラウザバー伸縮、指の遮蔽、長押しのOS挙動、低輝度、実機100ms以内の表示反応、実機GPU時間、60秒性能と3分発熱は未検証。
- 初見5人の発見検証、Gridの接触感を3人以上が支持する比較、最終美術承認は未実施。

G2-A3の体験評価を待って停止する。KASANE・AIMA・全編統合・追加演出へは進まない。
